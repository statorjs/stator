# Roadmap

How items earn a place here: Stator 1.0 shipped only after a full application ([the demo](https://demo.statorjs.dev)) was built against the API and every paper cut was logged and adjudicated. The roadmap keeps that method — **content doubles as evidence**. Examples pressure-test the framework; what they prove missing becomes a primitive; what they prove awkward becomes a recipe. The full gap analysis (with evidence and design sketches) lives in [`.chisel/docs/primitive-gaps.md`](.chisel/docs/primitive-gaps.md); items promote from there to here when the evidence is in.

This file lists what is open. What shipped is in the [changelog](packages/stator/CHANGELOG.md) and the specs under [`.chisel/specs/`](.chisel/specs/); each category ends with a one-line record of what left the list.

*Last revised 2026-11-22, at 3.0.3.*

## Committed for 3.1

The full plan, with what runs in parallel, is in [`implementation-plan-3-1-through-3-3`](.chisel/specs/implementation-plan-3-1-through-3-3.md).

- **Refused-dispatch reasons, over 4xx**: a guard calls `helpers.refuse(code, …)`; a response carrying a refusal is a 422; the client reads 4xx bodies instead of discarding them, and failure events bubble from the element that sent the event. Specs: [`refused-dispatch-reasons`](.chisel/specs/refused-dispatch-reasons.md), [`client-side-event-error-handling`](.chisel/specs/client-side-event-error-handling.md).
- **`defineApiRoute` takes any HTTP method**: `method: 'POST'` on a command route is a type error today. Spec: [`defineapiroute-takes-any-http-method`](.chisel/specs/defineapiroute-takes-any-http-method.md).
- **The `reads` rename, as aliases**: `Stator.machines([...])` and `machines:` on routes, `peers:` and `helpers.peers` on machines; old names deprecated, removed at 4.0. Spec: [`the-reads-family-rename`](.chisel/specs/the-reads-family-rename-ships-as-aliases-machines-on-routes-peers-on-machines.md).

- **Body size limits for uploads and API routes**: `requests.maxBodyBytes` in config and `maxBodyBytes` per route, 413 over the limit. No default in 3.1 (a warning over 1 MiB); 1 MiB at 4.0. Spec: [`request-body-size-limits`](.chisel/specs/request-body-size-limits-for-uploads-and-api-routes.md).
- **An unlisted image width is answered, not refused** *(merged, waiting for the release)*: `?w=` off `images.widths` redirects to the next listed width up, and past the largest to the original; it was a 400, which a browser shows as a broken image. Found on tonysull.co, where a package helper asked for a width the site does not list. It belongs with the refusal work: the server gives a request it cannot take as given a useful answer. `stator dev` logs the first request for each unlisted width, with the page that asked, so the template gets found. Spec: [`an-unlisted-image-width`](.chisel/specs/an-unlisted-image-width-is-answered-by-the-next-one-up.md).
- **Machine-hash esbuild target → `'node24'`**: `server/machine-hash.ts` still bundles for `node20`. The hash is taken over the bundle's minified output, so only a machine using syntax esbuild rewrote for Node 20 (an import attribute, for example) gets a new hash; measured across seven apps, the two targets produce identical bytes. Still a minor with a changeset that says so. The literal stays a literal: the hash has to come out the same on any Node.

## Example starters

**Why this category**: starters are *app shapes people build on* — they teach by being run, gutted, and extended, and every one is scaffoldable (`pnpm create stator my-app --template <name>`). They're also how the framework gets stress-tested: the storefront demo found eight real bugs before 1.0; each new example is aimed at surface nothing else exercises.

- **`planning-poker`** *(parked 2026-11-22 with presence)* — multiplayer estimation rooms: URL-keyed shared state, per-session roles, reveal mechanics. It was meant to scout the presence gap; both wait for a real app to need who-is-here.
- **`drydock`** *(design note first)* — a palette-first issue tracker: ⌘K as the primary UI (SST-console lineage), issues in real storage with FTS search, workflows as guarded machines, a live board. Providers are a discovered directory, execution is serializable data (navigate / dispatch / flow — never a closure, so the palette adds no attack surface), and command availability is *derived* from the charts — mutation commands never declare `when`, the machine already knows. Async search runs as an abortable entry effect with stale-guarded completions streaming in over SSE. Designed in [`command-palette-starter`](.chisel/specs/command-palette-starter-providers-and-derived-availability.md). *Motivation*: the palette decomposes into server problems (global registry, search over storage, viewer-gated results, execution as dispatch) — and it scouts seams nothing else reaches: datasets under machines, hot-path async loads, **session-scoped live channels** (second forcing function after presence), the instance-machine gap, and ranked keyed moves on the identity seam.

Shipped: `minimal`, `todomvc`, `desksmith`, `live-poll`, `guestbook`, `with-auth`, `stockroom`, `indie-blog`, `weather`, `registration`. The reference storefront stays in `apps/store` and scaffolds via `--template github:statorjs/stator/apps/store`.

## Docs recipes

**Why this category**: recipes are *patterns you graft into an app you already have* — problem-shaped, short, searchable, and far cheaper to maintain than workspace members. They live in the docs' Recipes sidebar section. New recipes promote the same way: an example proves the pattern, the recipe distills it.

- **SEO for your site** — Tier 0 of the SEO surfaces spec (see Primitives): robots/sitemap as data routes, layout-owned head, the JSON-LD component, satori OG as app code. Not written yet.
- **Running scripts** — seeding and maintenance with `node --env-file-if-exists=.env --import @statorjs/stator/register <script>`, with a seed example and `build.include: ['scripts']` for production. Docs only; it replaces `stator exec`, which is parked.

Shipped: authentication, where data lives, receiving webhooks, file uploads, server-only events, sealed state, startup & background work, defer vs machine, gated routes & redirects, collections of workflows, updating from a template.

## Primitives

**Why this category**: these are the gaps where our own code stepped *outside* the framework to solve a problem — the tell that separates a missing primitive from a missing recipe. Only high-confidence items appear here; the speculative tail stays in the gap analysis until an example promotes it.

- **Event payload schemas** *(3.2; required at 4.0)*: events are declared with `events({ TYPE: schema | null })`, the type is inferred from the map, and the schema validates where an event enters from outside (`/__events`, API-route `dispatch`, `dispatchToApp`); a failure is a 422 refusal. Bring your own Standard Schema validator: Stator ships none and re-exports none, and Valibot is the documented default. `events.schemas` is `warn` in 3.2 and `require` at 4.0, when every event on a `defineMachine` machine has a schema. Spec: [`event-payload-schemas`](.chisel/specs/event-payload-schemas.md).
- **Claims readable in layouts and components** *(parked 2026-11-22)*: an IndiePub theme layout can't show the signed-in owner an Admin link without every route passing the owner down, because `Stator.request` is route-only. Since a claims read withdraws derived caching, a layout that reads claims would make every page using it uncacheable, so the link is dropped instead. Revisit when a layout needs per-visitor data that can't be dropped.
- **Ambient by-def reads + a typed requirement channel** *(design note first)*: components can't own `Stator.reads` (route-only, correctly), so the weather refactor threads `weather={weather}` through every tile — prop-drilling *state*. A component should read a machine by its imported def from the ambient request context (`read(WeatherMachine, …)`, symmetric with client `dispatch(Machine, …)`), with the dependency carried in the type and enforced up the tree: any renderer must provide the machine or propagate the requirement until a route discharges it — a compile error, not today's runtime throw. Designed in [`ambient-by-def-machine-reads`](.chisel/specs/ambient-by-def-machine-reads-with-a-typed-requirement-channel.md). *Motivation*: prop-drilling shared state is the first DX wall a component tree hits at scale; the fix is inversion of control done with types.
- **Presence** *(parked 2026-11-22; needs evidence)*: the SSE registry holds every connection but exposes only `activeConnectionCount()`. A full design exists ([`presence`](.chisel/specs/presence-a-read-over-live-connections-a-debounced-watch-and-the-crdt-boundary.md)), including where Stator stops short of CRDTs, but its motivation was a thought experiment and an unbuilt example. If a real app needs who-is-here, the smallest piece is the registry read alone. Design note: [`presence-and-demand-gated-polling`](.chisel/docs/presence-and-demand-gated-polling.md).
- **Per-record timers and child machines** *(spec drafted; revisit trigger met)*: `after` is per state, and a machine holding a collection has one state for every entry, so a per-entry retry backoff or expiry has no home. indie-blog hit it twice (outbox retries, mention verification), which is the second real app the revisit trigger asked for. Today's answer is the collections-of-workflows recipe. Spec: [`per-record-child-machines`](.chisel/specs/per-record-child-machines-composing-a-collection-of-workflows.md).
- **SEO surfaces** *(staged; `revision()` on data GET routes shipped)*: what remains, in order — the recipe above; **`Stator.head({...})`**, route-only head-as-data through the existing `</head>` injection seam, with three apps' worth of prop-threading evidence, sharing the head-contributions note's object shape so components can extend the same API if their trigger ever fires; then `staticRoutePaths()` + `sitemapXml()` helpers once a second app copies the recipe. Runtime-enumerator protocols (a `getStaticPaths` analog) are rejected — the app's own store query is the enumeration. OG generation stays out. Spec: [`seo-surfaces`](.chisel/specs/seo-surfaces-route-head-as-data-runtime-sitemaps-and-the-revision-hook.md).
- **Never-stale pages — reads-graph surrogate keys** *(layer 4 of the cacheable read path; its own minor)*: the framework already proves a page anonymous-identical from its declared `reads` and emits `Cache-Control` itself. The upgrade tags each response with the machines it read and purges the CDN the moment one commits — the SSE fan-out hook already knows the moment. Spec: [`the-cacheable-read-path`](.chisel/specs/the-cacheable-read-path-lazy-sessions-derived-cache-control-and-the-surrogate-key-upgrade.md).
- **A session-scoped region on a cached page** *(parked 2026-11-22; needs evidence)*: a real server cart in a cached header. A route that declares any session-machine read establishes a session on GET and loses the derived `Cache-Control`. A full design exists (late routes and a load-time sync, with request locals: [`per-visitor-content-on-a-cached-page`](.chisel/specs/per-visitor-content-on-a-cached-page-late-routes-request-locals-and-the-load-time-sync.md)); the evidence so far is Stator's own demo store and landing page. An island fetching a data route is the answer meanwhile.
- **`defer` placeholder-and-stream**: the designed-in, non-breaking upgrade to `defer` — send the placeholder, stream the resolved region. Today every defer on a page is awaited before the response starts.
- **Image follow-ups** *(each additive; none promoted)*: a `?q=` quality allowlist, blur-up thumbhash placeholders, an `images.resolveUrl` CDN/URL-builder seam, a webp `<Image>` default, density descriptors, multiple mounts, smarter `sizes` defaults, and versioned `?v=` URLs (deferred with a named trigger). List and adjudications in [`images-are-part-of-stator`](.chisel/specs/images-are-part-of-stator-transformer-adapter-image-endpoint-image-and-picture-components.md).
- **`fonts` config** *(evidence-gated)*: self-hosted webfonts are deliberately files-plus-CSS today, and the [styling-and-assets guide](apps/docs/src/content/docs/guides/styling-and-assets.md) carries the Fontsource copy-script recipe, dogfooded by indie-blog. The first-class shape, IF the paper-cut log ever demands it: a `fonts` declaration consumed at build/dev that emits `@font-face` CSS and per-route preloads through the head pipeline, with metrics-adjusted fallbacks (`size-adjust`/`ascent-override` — the CLS half that makes `next/font`/fontaine genuinely valuable) as the part worth first-classing.
- **Durable schedules** *(pairs with durable effects)*: `after` timers are in-memory and drop on restart by design (a hydrating host re-arms with elapsed credit); a schedule that has to survive on its own has no home.
- **Declarative clock/subscription primitives — still deferred**: external inputs that drive machines over the process lifetime. Today the userland form is `boot.ts` dispatching via `dispatchToApp`. Decomposition: **poll = a recurring clock → an effect → events** (a recurring clock isn't expressible via a self-looping `after`, which won't re-arm); **push = a subscription source** (owns a connection, emits data-bearing events, the genuine inbound dual of an effect). *Why it waits*: the userland pattern is the evidence vehicle and it works — pre-building a declarative `clock`/`source` seam now is exactly the bind-family over-commitment we don't repeat. *Promotion trigger*: shutdown-cleanup pain in a real app that the `boot.ts` teardown doesn't cover.

Shipped: images (2.11, with the `images.immutable` opt-in and content-hash validators after it), the cacheable read path layers 1 and 3 (2.10; layer 2 adjudicated out of framework surface), `defer`, the snapshot hydration policy (2.6) and its follow-ups (2.15: package versions in the hash, release-independent hashing, `seed`, an honest deploy report), state timeouts (`after`), `serverOnly` events (2.3), session identity and auth primitives (2.3–2.4), data GET routes with `revision()`, `boot.ts` (2.5), client-to-app dispatch through gateway machines (a direct send is a 403 and a type error since 3.0.3), and component libraries with library islands (`build:lib` in 2.12, library islands in 3.0).

The compiler-derived client-dispatch allowlist shipped in 3.0 as the **per-route event gate**: `/__events` accepts an event only when the page it names sends it, read from source, with `events: { gate: 'warn' | 'off' }` as the escape. It went out as a gate rather than the `stator check` lint this file once proposed as its first step.

## Developer tooling

**Why this category**: not app-facing primitives — DX for *building* with Stator. Held to the same evidence bar (a spike proves it before it ships). The framework owns the dev loop end to end since the Vite exit, so dev surfaces are edits to our own code, not integrations.

- **`stator exec`** *(parked 2026-11-22)*: the gap that motivated it was documentation, now closed, and Node 24's `--env-file-if-exists` covers env loading. Revisit when a real script needs the resolved config or what `boot.ts` sets up. Spec: [`stator-exec`](.chisel/specs/stator-exec-run-a-script-with-the-app-s-loader-and-config.md).
- **`stator inspect [Machine]` and `stator viz [Machine]`** *(fast follows to the Machines tab)*: a one-shot CLI chart print with no server needed, and Mermaid `stateDiagram-v2` output to paste anywhere. Both reuse `describeMachine`. *Deliberately out*: dev session enumeration (an optional `Store.listSessions()` — revisit on demand from a multi-session example) and island-machine cards.
- **Client-side time-travel debugger** *(spike first)*: scrub back through what happened by inverting the wire patches on the client — the framework already ships fine-grained, cleanly-invertible DOM ops, so a patch-inverse undo stack + a scrubber in the inspector gives DOM/visual history with **no** server-side rewind. *Motivation*: Redux-style time-travel is a top-tier debugging win, and Stator is unusually well-positioned for it; the design + open edges (client islands, focus/scroll, keyed-list ordering) live in [`client-time-travel-devtool`](.chisel/specs/client-time-travel-devtool.md). Spike first because those DOM edge cases are where the surprises hide.
- **`stator check` machine lints (flow verification beyond types)** *(unscheduled; evidence-gated)*: static checks that types alone don't give. Stator holds *both* halves in one compile pass — the event-emission sites and the accepting chart — and the per-route event gate now extracts the emission half for real.
  - **Sound tier (no false positives, ship first):** an event in the union handled in *no* state; a state with no incoming transition; an event handled only in states unreachable from `initial`. Pure graph analysis on the chart, and most frameworks *cannot* do it (their reducer is opaque JS).
  - **Heuristic tier (opt-in warnings, research-y):** "this button, in the render context where it appears, sends an event the state it renders under does not handle." Tractable only for the idiomatic conditional pattern, delivered as warnings, never a hard error.
  - **Honest limits:** guards make "will this commit" undecidable — checks reason about the *structural presence* of a handler. And events arrive from non-UI sources too, so "dead" means handled-nowhere, not merely UI-unsent.
  - **Also here:** a build-less diff naming which machines a pending change would reset (`stator build` reports it today).

  *Promotion trigger*: an example whose UI ships a dead event a check would have caught. Worked examples in [`introspection-manifest-and-checks`](.chisel/docs/introspection-manifest-and-checks.md).
- **Introspection manifest (machines + components)** *(unscheduled; evidence-gated)*: a build-time JSON manifest of the declarative surfaces — machines (states, events, guards, selectors, effects, timers) and components (props, island `static attrs`, refs, regions). The machine half's runtime walk exists as `describeMachine`; the manifest is that walk run at build plus the component half. The highest-value first output is **statechart visualization in the inspector**. Later consumers: auto-generated reference docs, per-state/event test scaffolding, a component gallery rendered against mock machine snapshots, LSP enrichment. *Promotion trigger*: a user or example that hand-builds a state diagram, a component gallery, or repetitive per-state test stubs. Fuller framing in [`introspection-manifest-and-checks`](.chisel/docs/introspection-manifest-and-checks.md).
- **Agent tools from the state graph** *(evidence-gated; experiment defined)*: an agent's view of any page — the reads as data, event schemas, and the currently-valid actions — derived from the compiled state graph so the affordances are never stale. The skin is now WebMCP (`document.modelContext.registerTool`) rather than a bespoke HTTP envelope. The genuinely new cost is build-time schema extraction for the erased event union, which event payload schemas (see Primitives) would pay for. *Gate*: the Desksmith agent experiment — an agent completing add-to-cart→checkout through the tools must beat the same agent DOM-driving, on steps/tokens/reliability, or the idea doesn't earn the surface. Specs: [`agent-readable-routes`](.chisel/specs/agent-readable-routes-affordances-from-the-state-graph.md), [`the-webmcp-skin`](.chisel/specs/agent-tools-from-the-state-graph-the-webmcp-skin.md).

Shipped: machine state inspection (`describeMachine`, `/@stator/inspect`, the Machines tab), the Vite exit (native dev in 2.6, Vite removed in 3.0 with esbuild bundling islands in dev and build), the editor following the project's Stator (`@statorjs/stator/editor`), and source maps from `.stator` files for server modules and islands.

## Surface hygiene

**Why this category**: not features — debts against the small-and-legible surface the vision promises, recorded here so they're paid deliberately instead of discovered by a user.

- **Major-cutover pairing** *(semver policy, not a task)*: when a change *could* be shaped as breaking but a non-breaking shaping exists, ship the non-breaking shaping now and record the deferred cutover here — so the next major that lands for other reasons carries the cleanup. *Minor today, ride a major later.* 3.0 carried the ledger: the flat `createApp`/`createDevApp` keys, the Toolchain re-export from `/server`, the blanket `/__events` 400 for events no chart handles, and the Node 24 floor. The next major's list is the [4.0 ledger](#40-ledger).
- **Scaffold toolchain devDeps drift**: `@statorjs/stator` in scaffolded apps is version-managed (the `STATOR_RANGE` sync + changesets), but the starters' other devDeps are hand-pinned — `typescript ^5.6` in every one, and a `tsx` devDependency in `indie-blog` that none of its scripts use (`apps/store` still runs its own `server.ts` under `tsx`). Follow-ups: bump them, and add a freshness guard so they don't silently re-drift (pairs with scaffold-smoke CI). *Motivation*: the scaffold is the first-run experience; stale tooling is a silent, compounding papercut on every new app.
- **Entries not marked resolved in the rebox log** *(check each against 3.0 first)*: frontmatter is parsed as plain `.ts` while the type-checker's virtual file models it as JSX (entry 2); a conditional wrapper around a `child="x"` slot marker silently falls into the default slot (entry 4); author attributes on an island's root element are silently dropped (entry 7). [Log](.chisel/docs/rebox-paper-cuts.md).
- **Spec statuses are stale**: a number of specs are still `draft` for work that shipped (session identity, the Vite exit, lazy sessions, image caching, the snapshot follow-ups among them).

Shipped: the `/server/runtime` tier split (2.12, re-export removed in 3.0), the reactive-model regrounding that removed `bind:`/`@set` (2.0), seam consolidation (one `attrValue` in `wire/`, seam-contract tests), and log-level control with a quieter production default (`logging.level`, `LOG_LEVEL`).

## Runtime correctness

**Why this category**: not new surface — places the framework silently does the *wrong* thing on a natural template, found by an example and confirmed with a runnable repro. These jump the evidence queue: a correctness bug on a documented pattern is a bigger liability than any missing primitive.

- **The compose/identity seam is the standing complexity risk** *(watch, not a task)*: slot scopes, key scopes, element ids — the addressing layer under the bindings. It generated the composition-boundary bugs, and a new binding *kind* re-tests it. The diff-*kind* surface stays small on purpose (see [`recompute-model`](.chisel/docs/recompute-model.md)); the guardrail is on this seam — a new binding kind or position earns its place only after it regression-tests the seam and clears the same evidence bar as any primitive. The guardrail's first hard call: item reads inside `when`/`match`/`defer` arms are a compile error, not a supported position. *Revisit trigger*: two more real templates carrying find-by-id machine reads inside arms for item-local data.
- **A page that peeks claims is marked `public` for everyone** *(confirmed 2026-11-22; patch specced: [`a-claims-read-always-withdraws-derived-caching`](.chisel/specs/a-claims-read-always-withdraws-derived-caching.md))*: the anonymous render of a claims-peeking page goes out `public` with no `Vary`, so a shared cache may serve it to a signed-in visitor. When the two renders allocate different slot ids (a plain ternary on claims), patches for the signed-in render land on the wrong elements of the anonymous HTML. Details and fix candidates in the [plan](.chisel/specs/implementation-plan-3-1-through-3-3.md).
- **A CDN-stale live page reload-loops after a deploy** *(confirmed 2026-11-22; patch specced: [`a-build-mismatch-reload-is-guarded-against-a-stale-cache`](.chisel/specs/a-build-mismatch-reload-is-guarded-against-a-stale-cache.md))*: a build-id mismatch on `/__sse` triggers a bare `location.reload()` with no guard, and a cache that keeps serving the old HTML loops the tab until the edge entry expires.
- **A session change under an open tab lands patches on the wrong elements** *(confirmed 2026-11-22; patch specced: [`a-layout-fingerprint`](.chisel/specs/a-layout-fingerprint-reloads-a-page-whose-ids-no-longer-match.md))*: slot and element ids are positional, so a plain conditional or component choice on a value that changes after the page loaded (claims, on sign-in in another tab, sign-out, or Back after sign-in) shifts every id after it when an arm holds a binding, and the next sync is applied to a page laid out differently. `when()`/`match()` are unaffected. Details in the [plan](.chisel/specs/implementation-plan-3-1-through-3-3.md).
- **A page served by a catch-all is patched from the wrong route** *(confirmed 2026-11-22; patch specced: [`a-page-served-by-a-fall-through-names-its-route`](.chisel/specs/a-page-served-by-a-fall-through-names-its-route.md))*: a GET falls through a 404 to a catch-all, but `/__sse` and `/__events` use the first route matching the path, so the catch-all's page is synced, patched and event-gated from a different template. The layout fingerprint exempts 404 renders until this lands.
- **The event gate is by event type, not by machine**: `/__events` accepts an event when some page offers that type, whichever machine it targets. Tightening it to (machine, type) is future work.
- **Coalescing outbox** *(measurement-gated)*: at most one pending write per slot on a connection's queue. Bounded writes and the per-connection write queue shipped in 2.10; this is what remains of the [SSE delivery spec](.chisel/specs/sse-delivery-bounded-writes-the-outbox-and-fan-out-at-scale.md).

Shipped: the composition-boundary bugs (#20), comment-marker regions and template-parsed patches with real-browser tests (1.8), and bounded concurrent SSE writes with a per-connection write queue (2.10).

## Investigations

**Why this category**: questions with no evidence on either side yet — too broad to be a primitive, too structural to wait for a paper cut. Each earns a design note before any code.

- **Internationalization** *(nothing designed)*: Stator has no i18n story — no message catalogs, no locale negotiation, no localized formatting. The server-canonical model is unusually well placed for one: locale is session state, every render is server-side (no per-locale client bundles), and patches are per-session by construction — a locale change is "just" a state change that re-renders. Open questions: where catalogs live, template ergonomics for messages, date/number formatting at the selector level, and whether locale is a session machine or ambient request context. No user demand yet; a scout-before-asked item.
- **Fan-out cost at scale** *(nothing built; measurement-gated)*: fan-out is **O(N observers)** of CPU and allocation per dispatch, on one thread. Roughly, 1000 viewers × ~50 bindings ≈ 50ms of event loop per dispatch. Two levers exist before any architecture change — **compute once per group** (connections on the same route with the same baseline produce byte-identical patches) and **coalescing fan-out jobs** so M writers cost one pass rather than M. "Use more cores" is not a separate answer: Node scales across cores with `cluster`, which for in-process fan-out and app machines *is* the multi-replica problem, so it collapses into the Redis backplane. None of it should be built before instrumentation says where a real app sits. Analysis in the [SSE delivery spec](.chisel/specs/sse-delivery-bounded-writes-the-outbox-and-fan-out-at-scale.md).
- **`<head>` contributions from components** *(design note recorded; evidence-gated)*: a component cannot contribute a tag to `<head>`. This is the *write-up* dual of ambient by-def reads' *read-down* — if both ship they share the typed-requirement-channel idea and must be designed aware of each other. Stator's sync render contract defuses the historically hard part (timing). Promotion trigger has not fired; design in [`head-contributions-from-components`](.chisel/docs/head-contributions-from-components.md).

Adjudicated: **route injection** is rejected in favour of package handlers behind one-line mount files ([`no-route-injection`](.chisel/specs/no-route-injection-package-handlers-mount-files-and-the-layered-indiepub-shape.md)); its open gate, whether a package can ship `.stator` files, closed with `build:lib` and library islands in 3.0.

## Known infrastructure

Tracked in the gap analysis, unscheduled: a Redis fan-out backplane (multi-replica), durable effects with an outbox, `waitFor` coordination, lazy machine refs, a user lifecycle (a third fan-out scope: one user's connections across devices), transient context keys, and rate limiting (likely a recipe over middleware).

## 4.0 ledger

**Why this category**: everything the next major carries, in one place. 4.0 exists because every event on a `defineMachine` machine must have a schema; the rest rides along.

**Committed.** Each has a non-breaking form shipping first.

| Cutover | Non-breaking form | Ships in |
| --- | --- | --- |
| Every `defineMachine` event has a schema: `events.schemas` becomes `require`, `{} as Events` is removed. Client-only `machine()` machines are exempt | `events({ … })` opt-in, `warn` at dev boot | 3.2 |
| Old `reads` names removed (`Stator.reads`, `reads:`, `helpers.reads`); internal fields renamed | `machines` and `peers` aliases, old names deprecated | 3.1 |
| 1 MiB default request body limit | `requests.maxBodyBytes` opt-in, a warning over 1 MiB | 3.1 |
| `zod` removed from the framework's dependencies | hand-written envelope check | 3.2 |
| Root `media/` convention dir | held back from the images release | 2.11 |

**Candidates.** Breaking, not yet designed; each needs a spec before it is committed.

- **A route's 404 is final, with an explicit hand-off.** Today a GET route's 404 falls through to a catch-all, so a status code doubles as control flow, and `/__sse` and `/__events` had to learn which route served a page. The candidate: a 404 means "this is mine and it is not found", and a route calls something explicit to pass the request on (to a catch-all or `routes/404.stator`). Every app with a `[slug]` route and a `404.stator` relies on the fall-through today, so it needs a migration story.
- **The event gate by (machine, type).** It is by event type today. Tightening it can refuse events an app currently sends.

**Open decisions.**

- The `serverOnly: [...]` list on a machine, now that `serverOnly<T>()` and `serverOnly(schema)` declare the same thing per event: deprecate the list in 3.2 and remove it here, or keep both.
- What `events.schemas: 'off'` and `'warn'` mean once `require` is the default: removed, or kept as an escape hatch.
- How `stator build` and `stator check` enforce the schema requirement. Neither imports machine modules in 3.x; the 3.2 report runs at dev boot only.
