Images are part of Stator. Declaring `images: { dir }` in `stator.config.ts` mounts an image endpoint over the directory: the URL's extension is the delivery format (request `x.webp?w=800` of a stored `x.jpg` and the server converts and resizes to honor it — never `Accept`-header or user-agent negotiation), widths come from an allowlist, variants cache on disk, and every response carries an ETag with bodyless 304 revalidation. Transformation runs through a swappable `ImageTransformer` adapter with sharp as the lazy-loaded default — an unconfigured app mounts no routes and never loads it.

Rendering ships on the `components` subpath: `<Image>` emits CLS-safe markup (`width`/`height` always present, `srcset` over the endpoint, lazy + async defaults), `<Picture>` adds modern-format `<source>` chains with the stored format as fallback, and `getImage()` is the pure resolver beneath both. Dimensions are required, always, and come from data: probe them once at upload with `probeImage()` and store them — renders are synchronous and never do image IO. Remote URLs render untouched and require dimensions like everything else; GIFs and SVGs render as originals only.

Cropping is one word in one vocabulary: `crop` is a ratio (`1` square, `16 / 9` widescreen) the endpoint cover-crops to via `?w=&h=`, and the emitted `width`/`height` describe the *cropped* result, so the reserved box matches the pixels that arrive. Both axes stay allowlisted — widths from `images.widths`, ratios from `images.aspectRatios` (square, 4:3, 3:2, 16:9 and portrait duals by default) — so photographic crops work while the variant space stays finite, and a ratio the endpoint would reject is a render error rather than a silently dropped source. `<Picture sources>` is for geometry that *varies by breakpoint* (art direction: each entry crops under its media condition, crossed with every format including the stored one, and overrides the component-level crop there); a single fixed geometry like a thumbnail grid is just `crop` on the component. Component srcsets and crop validation read the resolved config from the render state, so markup can't drift from what the endpoint accepts.

Loading control decomposes. `priority` remains the one-word LCP escape hatch (`loading="eager"` + `fetchpriority="high"`), but the attributes it stands for — `loading`, `fetchpriority`, `decoding` — are settable directly with their native names and values, because the rollup assumes a hero and a thumbnail grid wants its whole first row eager with only the first at high priority. The shorthand and its constituents are mutually exclusive in the types, so `<Image priority loading="lazy">` fails to typecheck instead of resolving silently.

The design was proven end-to-end in `examples/indie-blog` before promotion; the example migrates onto this surface in a follow-up.
