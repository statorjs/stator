Library islands read source through the TypeScript API, so an import that appears only in a comment or a string is never followed, stubbed or counted, in route CSS, route islands, the `build:lib` machine stub, the tags and machines read back from a published client entry, and dev's live-reload graph. A server machine module is defined once for `build:lib` and for the island bundler: a module importing `defineMachine` from `@statorjs/stator/server` or `@statorjs/stator/machine`, named, aliased, as `import * as S` used as `S.defineMachine`, or through a local module that re-exports it. An app island importing such a module outside `machines/` now gets the `{ name }` stub instead of the machine's code. The walk resolves a package's `exports` under the `import` condition, so an `import`-only export is reached, and probes an extensionless relative import as `.ts`, `.js`, `/index.ts` and `/index.js`. A reached package module named like compiled output in a shape `build:lib` never emits, such as `x.stator.js`, fails `stator build` and `stator check`, naming the package and the file. The browser-safety check derives the server-side subpaths from the package's own `exports`, so `@statorjs/stator/components` is now refused in a client entry. `checkStack` takes a `routesDir` option. Compiled output is unchanged.
